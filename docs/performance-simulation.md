# 本地性能模拟（2026-10-24）

目标是验证 `fa696dc` 网络/IPC 优化的具体收益。当前生产代码为 `a96123e`；基线按 `bc9a345` 的 HTTP 和 FrameDecoder 算法在模拟程序中复现。两边使用相同的新依赖和编译器，因此不能用这些数字评价依赖升级本身，也不是两个完整版本的整机对比。

模拟程序：[`examples/performance_sim.rs`](../examples/performance_sim.rs)。所有 TCP 流量只在 `127.0.0.1`，没有操作真实拨号、网卡、路由或已安装服务。编译器 `rustc 1.99.1`，release 构建，x86_64。Windows 结果来自本机 Windows 进程；Linux 结果来自 WSL。运行期间没有隔离其他系统负载，没有统计显著性分析。

## Windows 结果

耗时为重复采样中位数；HTTP 正常请求 30 次、慢响应各 5 次、IPC 7 次、调度模型 3 次。取消连接和缓存边界各执行一次。

| 场景 | 优化前 | 优化后 | 解读 |
| --- | ---: | ---: | --- |
| 正常 HTTP 完整响应 | 0.370ms | 0.388ms | 单轮约慢 0.018ms（4.9%），未体现正常请求提速；不能据此认定稳定回退 |
| 持续慢回包，配置 200ms 超时 | 1009.6ms | 202.4ms | 等待减少约 80%；新版按总截止时间失败，旧版继续等至 EOF |
| 探针只需响应头，响应体慢回包 | 1009.2ms | 0.576ms | 新版拿到完整响应头即可返回；节约的是这里人为设置的响应体等待 |
| 60KiB 无换行数据，每次仅输入 16 字节 | 22.35ms | 0.0489ms | 此极端碎片场景约快 457 倍；不能外推为整机或正常 IPC 提速 |
| 输入 4MiB 无换行数据 | 缓存全部 4MiB | 超过 64KiB 拒绝 | 单帧缓存有上限；不是进程 RSS 测量 |
| 8 个请求同时取消后 150ms | 8 个服务端连接仍在处理 | 0 个 | 验证异步取消能释放真实连接 |
| 探针串行/并行超时调度模型 | 4511.6ms | 3007.6ms | 约减少 33.3%；仅定时器模型，不是真实 ICMP/校园网测量 |

## 实验方法及限制

- HTTP 服务端立即发送完整响应头；慢模式再每隔 40ms 发送 1 字节，共 25 次。新版调用生产 `get_async`，旧版复现同步 socket + `read_to_end`。正常/慢响应每次交替测量顺序，服务端线程清理不计入请求耗时。完整响应模式在新版截止时返回错误，这个结果表示及时止损，并非更快完成同一份下载。
- 取消实验先确认 8 个连接均已发送响应头，再取消全部外层任务，150ms 后观察服务端处理连接数。响应体最长持续约 4 秒；旧版 `spawn_blocking` 内的请求仍继续运行，新版原生异步请求随 future 释放 socket。服务端通过写失败退出，观察值不是精确的内核关闭时延或线程计数。
- IPC 直接运行生产 FrameDecoder 和旧算法。60KiB 尚无换行，最终不输出完整帧，用于放大旧版反复扫描历史缓存的开销。另一次输入 4MiB：新版接受到 65536 字节，在下一块 4096 字节到来时拒绝并清空缓存；旧版全部积存。没有测量总内存、分配器开销或 RSS。
- 探针模型仅比较先 sleep 1500ms 再 sleep 3000ms 与并行等待两者，没有调用真实探针、ICMP 或状态机。实际掉线判断还受连续失败门槛、探测周期、退避和拨号耗时影响。
- 没有测 GUI 卡顿、DNS 阻塞、安装回滚、持续运行 CPU/RSS、带宽或真实断线恢复时间。不能得出“整个程序提速 X%”或“网速提高 X%”。主要证据支持异常等待受控、取消后的资源释放和极端 IPC 输入的处理效率。

## 原始结果与复现

- [Windows 原始 JSON](performance/2026-10-24-windows.json)
- [Linux 原始 JSON](performance/2026-10-24-linux.json)

Linux/WSL：

```sh
cargo run --offline --locked --release --example performance_sim
```

Windows 本机构建运行，或交叉构建后在 Windows 运行产出的 example exe：

```sh
mise exec -- cargo xwin build --offline --locked --release --target x86_64-pc-windows-msvc --example performance_sim
```

运行约 45 秒，进度使用英文 stderr，最终 JSON 输出到 stdout。需要允许本机回环 TCP。测试程序只会创建自己的临时监听端口；不会更改已安装产品配置。

验证：Linux 测试套件通过、示例 Linux clippy 通过、Windows 全目标 clippy 通过、`cargo fmt --check` 通过。第一次在受限沙箱运行测试时，本地监听端口创建被拒绝；允许回环 socket 后全套重跑通过。
